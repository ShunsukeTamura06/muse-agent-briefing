2　Museの守り

第三者の報告

それでもMuseから、確認のない通信で情報が持ち出された

セキュリティ企業NebuSecが、悪意あるWebページ1つで、会話履歴と記憶を外へ出せたと報告（11月20日）

何が起きたか

  • Museに悪意あるページを保存させると、内蔵ブラウザの弱点を突かれ、攻撃者のプログラムがMuseの作業区画の中で動いた（AIがだまされたのではない）
  • Sentinelは、本文のないGETなどの通信を「読み取り」とみなし、初期設定では確認なしで通す。攻撃者はこの規則の範囲内で、確認を一度も出さずに情報を送った（送り方の細部は非公表）
  • NebuSecによれば公開前に修正済み。何をどう直したかは公表されていない（同社単独の報告）

使う側の教訓

  • Muse固有の話ではない。読む・つなぐ・送るができるAIエージェントすべてに起こりうる
  • 確認ボタンがあるから安全、とは限らない
  • だから、何をつなぎ、何を許すかを、使う側が絞る

3　サイト側から見ると

事実（報道）と発表者の整理

サイト側からは、来たのが本人かAIか、確実には見分けられない

誰かがサイトを操作しに来たとき、サイト側が確かめたいのは次の4つ

① 来たのはどのAIか

Museか、別のAIか、ただの迷惑な自動アクセスか

② そのAIは、どのユーザーの代わりか

本当にそのユーザーがAIに頼んだのか

③ ユーザーは、AIに何を許したのか

見るだけか、買い物までか

④ AIは、その操作が取り消せないと分かっているか

購入やキャンセルを、このまま通してよいか

送信元などの痕跡から「たぶんAI」とは推測できても、外れることも、すり抜けられることもある（発表者の推測）。①〜④は痕跡からは確かめられないので、サイト側に残る手は「まとめて締め出す」くらいになる

3　サイト側から見ると

事実（各社の発表・仕様）

答え：Poppyは、AI専用の受付で①〜④に答えさせる

MetaとSierraが中心に作った共通ルール（2026年11月13日に1.0版。Sierraによれば、Shopifyの全ストアが対応）

サイト側の問い（前のページ）Poppyの受付での答え方
① 来たのはどのAIかAIが毎回、署名付きで名乗る。偽物は見抜けるが、通すかはサイト側次第
② そのAIは、どのユーザーの代わりかユーザーごとの番号で示す。AIの中でも人ごとに区別でき、Museごと締め出さずに済む。番号はサイト専用で、本名やメールは伝わらない
③ ユーザーは、AIに何を許したのか基本は、ユーザー自身がサイトの画面でログインし、許す範囲を選ぶ。AIが受け取るのはその範囲だけの許可で、パスワードは受け取らない
④ AIは、取り消せないと分かっているかサイト側が、許可の範囲ごとに「変更があるか」「個人データを扱うか」を宣言する。取り消せない操作は承認を待てる

AIがサイトを操作する方法は、サイト側が選ぶ：MCP（Claude CodeのMCPと同じ）、API、Webの画面、サイト側のAIとの会話など。
Poppyに対応していないサイトでは、AIは今まで通り人のふりをして画面を操作し、範囲の制限はない

事実（発表者の確認）

実例：航空会社の受付は、用途ごとに③と④を決めている

ターキッシュエアラインズのPoppyの設定ファイルを、発表者が日本語にまとめた（11月25日確認）

Museにやらせたいこと③ ユーザーが許すもの④ サイト側の宣言
フライトを探す何も要らない（ログイン不要）変更なし・個人データなし
予約を確認する予約番号と姓を伝える変更なし・個人データあり

実物の一部：poppy.json の "scope_hints"（表の順に並べ替え。ファイルは0.4版の書式）

"flights:search": { "changes": "none", "personal_data": false },
"bookings:read":  { "changes": "none", "personal_data": true },
"profile:read":   { "changes": "none", "personal_data": true }

3つとも "changes": "none"（変更なし）。AIに許せるのは「見る」ことだけで、予約の変更は受け付けていない

ただし、承認するのは、あなたの指示を受けたAIでもよい

ルールの例：最初に「20ドル以下の交換なら進めてよい」と伝えておけば、AIは毎回あなたに聞かずに承認できる。
サイト側には、本人が承認したかは確かめられない

実例：Shopifyのストアは「購入の準備」を取り消せない操作とし、購入を完了するのは買い手としている

次の問い

結局、AIに指示するとき、私たちは何を渡しているのか

12

まとめ：AIに指示するとき、私たちは何を渡しているのか

答え：私たちは、次の3つをAIエージェントに渡している。
どこで止まり、どこで止まらないかを知ったうえで任せる

① あなたとして操作する力

AIエージェントは、あなたのアカウントで、メールの送信や購入まで行える。危ない操作を止めるのは、AIとは別の許可の仕組み

Museでは：許可の仕組み（Sentinel）が止めるが、確認を一度も出さずに情報が持ち出された報告がある（p.6・p.8）

② あなたの情報

あなたがAIエージェントに読ませたメールや社内データは、AIの手元に渡る。誰が書いたか分からない文章も一緒に読むと、その指示で外へ送られうる

Museでは：メールの一文で請求書を転送する例（架空、p.5）。悪意あるページ1つで会話履歴が出た報告（p.8）

③ 承認する権利

「20ドル以下なら進めて」と決めておくと、その範囲ではAIエージェントがあなたに聞かずにサイトへ承認を送る。サイトはAIの申告を信じるしかなく、あなたが本当に承認したかは確かめられない

今日の例：Poppyのルールに載っている（p.12）。Museなら、そのルールで判断するのは許可の仕組み（p.6）

渡さずに済むもの：パスワード（Museは札だけ、Poppyではあなたがログイン。p.7・p.10）とカード番号（Museは使い捨て番号。p.7）
いつか「AIに使われる側」のシステムを作るなら：AI用の受付、操作の影響の宣言、サイト側での確認が設計のポイント
